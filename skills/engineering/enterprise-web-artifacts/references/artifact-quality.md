# Design and verify an operations artifact

Put the decision, metric definition and reporting period in the first viewport. Use scale and space to establish hierarchy. Pick one accent for attention and use the same ordering and units in the chart and table. Prefer direct labels and tabular numerals. Use a table for exact comparisons and an interactive control only when it changes what the reader can learn.

Use native buttons, labels, headings and table headers. Supply text or numeric equivalents for every color or graphic. Keep visible keyboard focus and sufficient contrast. Test at 320 CSS pixels, high zoom, keyboard-only navigation and print. Place a meaningful result in the source HTML when the file must remain readable without JavaScript. For dynamic status changes, use a short live summary rather than rereading the full page.

Separate data timestamps from generation timestamps. Reconcile source counts to displayed totals, document the denominator, and make zero, missing, stale and denied explicitly different states. Render supplied strings with textContent or DOM text nodes. Use an authenticated host for private queries or changes. An offline deliverable should make zero network requests, including fonts and analytics.

**Acceptance task.** With 1/2 and 2/8, the overall result is 3/10. Filtering to the second group yields 2/8. A zero-eligible group shows an undefined rate. Verify a functional filter, a static table, keyboard focus, mobile layout and the reader's ability to explain the denominator. Record which checks ran on a browser and which still need a work-tenant test. [W3C tables tutorial](https://www.w3.org/WAI/tutorials/tables/)
