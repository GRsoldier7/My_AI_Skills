# Create a ChatGPT work skill, plugin or Space

Choose the surface by the job and the features the work account actually shows.

| Job | Deliverable | First test |
| --- | --- | --- |
| One well-defined request | Prompt with input, evidence and a verifiable output | Try a missing-source case |
| Repeatable analysis or writing method | One named skill with trigger, steps and examples | Try a direct request and a neighboring task |
| Related skills that people should discover together | Plugin specification with audience, contained skills, optional approved apps and owner | Compare named invocation, implied invocation and a near miss |
| Ongoing analysis with the same instructions and files | ChatGPT Project instructions and a source index | Start a fresh project chat and check scope |
| A living briefing that colleagues can navigate | ChatGPT Space with a landing page and owned child pages | Verify a reader can find the current decision and its source |

**Create from scratch.** Pick one outcome, e.g. a weekly BI variance note. Write a trigger in the user's language, minimal required fields, a worked synthetic example, missing-input behavior and a definition of done. Keep variable data in the approved work project. For a plugin, specify one skill first and add another only when a second distinct task earns it. Name actions separately from instructions. Retain the original version, fixtures and a rollback copy. If migrating an existing Custom GPT, inventory its instructions, knowledge and any enabled capabilities separately, then replay the same cases before cutover. Check workspace availability before proposing native creation or migration.

**Space blueprint.** Draft a landing page answering “What decision are we tracking?”, followed by a metrics dictionary, a decision log and weekly briefs. Each decision has an owner, effective date, review date and link to the approved record. Choose the smallest audience. A source the author can read can contain information an audience should not receive. Record source pointers and approved summaries. Preview visibility and obtain the owner's instruction before creating or sharing pages. If Space is unavailable, return the same pages as Markdown and use approved Project instructions or a chat attachment. No API or Actions are necessary.

**Weekly metric page.** For disjoint, comparable groups, show each numerator, denominator and rate plus a reconciled all-groups row. Compute the total from the summed counts. When groups might overlap, label the combined result unavailable until the metric owner confirms the grain. Keep missing target and missing baseline distinct.

**Try it.** Given a 3/10 result and a missing target, draft a weekly page with the rate grounded, target labeled unknown, and no invented variance. A second request to “share it with everyone” produces a proposed audience and a review step. Record whether content quality, native discovery and audience controls were tested separately.
