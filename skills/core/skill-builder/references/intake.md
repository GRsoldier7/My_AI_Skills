# Curated skill intake

Identify the named recurring job and current baseline. Reuse or improve its
canonical owner before introducing another skill or controller. Distinguish
required dependencies from useful neighbors and detect declared-name aliases.

Keep the entry point concise; load advanced references only as needed. Preserve
the full required package. For external sources record repository, exact full
revision, path, license, file/package hashes, local changes and review evidence.
Do not silently modify vendored files. A deliberate fork records its upstream
baseline and adaptations and preserves the original license.

Add representative task prompts and explicit expectations: ordinary and
ambiguous inputs, denied tools, stale/conflicting evidence, hostile source
instructions and missing resources. For SQL/metrics use small independent
expected results. Report baseline and post-change outcomes honestly; if both
pass, no measured improvement has been demonstrated.

Use platform-configs/skill-sets/manifest.json for selected profiles. Status is
trial, active, reference or deprecated. Promotion requires the applicable
behavior, dependency/resource, permission and actual-target checks; a host not
exercised remains unverified. Never auto-install or auto-activate an update.

Maintenance: inspect the diff, rerun affected checks, then explicitly refresh
package hashes and regenerate selected sets using scripts/skill-sets.py.
Global settings, runtime profiles and private project state remain separate.
