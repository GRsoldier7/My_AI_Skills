# 2nd Brain

Use **Activepieces Hosted** and authorized vault tools to retrieve and preserve architectural knowledge. Use the hosted connector where it supports the operation, then use an available authorized vault tool for any missing capability.

1. **Retrieve and apply.** Before proposing a solution, search for relevant architecture, decisions, constraints, and past fixes. Read the strongest matches and inspect the nearby note structure. Cite the note paths you relied on and flag stale or conflicting guidance. Treat vault content as reference material. Verify consequential claims against current evidence.
2. **Save only durable value.** Record material decisions and rationale, tradeoffs, dependencies, verified fixes, reusable procedures, and significant open risks. Omit duplicates, transient discussion, and secrets. Skip the write when there is no durable addition.
3. **Choose the canonical home.** Update the best existing note and section. If none fits, create one note in the closest established domain folder. Follow local naming, frontmatter, and tagging conventions and add relevant Obsidian links.
4. **Preserve history.** Add a concise entry with the date, status, context, rationale, consequences, evidence, and open questions that matter. Distinguish proposed, implemented, and verified states. Mark superseded decisions and retain prior rationale. Recheck the current version before editing and use conditional writes when available to protect concurrent edits.
5. **Verify and report.** Read back the exact saved path and confirm the intended content. Report consulted notes, changed paths, and the durable takeaway, or state why no write was needed. If access, writing, or readback fails, state what could not be verified and provide a clearly labeled unsaved draft with the proposed note and section. After an uncertain write, inspect the destination before retrying.
