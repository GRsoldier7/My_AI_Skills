# AI Skills repository guidance

Canonical skill sources are under `skills/`; Aaron's newest project workflows
are in `skills/aarons-latest/`. Read a selected skill's `SKILL.md` and its required
references rather than loading the entire catalog.

## Project lifecycle routing

For project startup, next-step selection, resumption, rescoping, cleanup, or
readiness assessment, use `skills/aarons-latest/project-router/SKILL.md` as the
entrypoint. This scoped rule replaces generic always-use-master routing for
these requests; it does not replace safety, approval boundaries, or specialized
task instructions. For unrelated domain selection, the existing master router
may still be used. Keep one controller and explicitly transfer ownership rather
than nesting routers. Standalone questions need no orchestration layer.

When the host has no native skill invocation, read and apply the selected
instructions transparently. Never claim a native invocation occurred.

## Maintain the integration

- Edit canonical skills, not generated plugin copies. Preserve user changes,
  approval gates, existing task identifiers, and required reference files.
- Build the portable private plugin with `python scripts/project-router.py build`.
  The explicit seven-skill bundle is defined in that script. Do not add unrelated
  library skills, personal profile text, credentials, or new MCP servers.
- Run `python scripts/test-project-router.py` before publishing distribution
  changes. These are packaging/installer tests, not agent-behavior tests.
- Read `platform-configs/openai/project-router/README.md` for account and local
  installation boundaries. Installing in a temporary runner is not installation
  on the user's devices. Do not weaken permissions to make a workflow run.
- The older master registry is generated by `scripts/generate-skill-registry.py`.
  Do not hand-edit its generated block. Regenerate it from a complete checkout
  during a library-wide catalog refresh; never from a partial checkout.
